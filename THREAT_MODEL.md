# Edge Mail threat model

This model covers the deployed personal Workers and the release and recovery tools in this repository. One installation can serve several users and shared mailboxes. A signed-in user can legitimately have read access to one mailbox and edit access to another. The Cloudflare account administrator controls the infrastructure and can read its storage. The model assumes that the account, identity provider, release machine and personal secrets vault remain under the operator’s control.

## Assets and boundaries

| Boundary | Asset and security objective | Enforcement |
| --- | --- | --- |
| Mail sender to Email Routing | Preserve the SMTP envelope and original bytes. Treat sender-authored headers and content as untrusted. | The Worker resolves the envelope recipient, limits raw size and stores envelope metadata with the MIME in a single R2 write. Authentication results depend on the first authentication-results field and its trusted authserv-id. [Receipt handler](src/ops/receipt.ts#L31) and [wire parser](src/wire.ts#L11). |
| Browser or service to app | Restrict each mailbox operation to an active user with the required role. Reject cross-origin writes. | Access assertion verification, user lookup, mailbox-scoped SQL and origin checks guard the API. The staging verification identity has an explicit read-only path. [Authentication](src/auth.ts), [authorization](src/ops/access.ts), [HTTP entry point](src/http.ts) and [staging entry point](staging/worker.ts). |
| Mail content to reader | Keep sender-controlled HTML, links and attachments away from the app session and browser storage. | The app issues short-lived, scoped bearer links. The sibling host rechecks current access, serves sanitized HTML in a sandboxed frame, and forces attachment download. The parent checks the frame and URL scheme before presenting a link. [Ticket redemption](src/content-ticket.ts#L36), [formatted content](src/ops/formatted.ts#L93) and [parent frame](web/formatted.tsx). |
| Author to outbound provider | Preserve the private Bcc envelope, respect revocation and limit duplicate or unauthorized sends. | Drafts belong to their author. The outbox takes an atomic claim, rechecks authority and sending identity, and reserves recipient units before submission. A lost acknowledgement goes to operator review. Shared delivery summaries include only visible recipients. [Dispatch claim](src/ops/dispatch.ts#L9) and [delivery summaries](src/ops/delivery-events.ts#L70). |
| Device to live or offline data | Keep messages scoped to the signed-in account and each authorized mailbox. | WebSockets carry invalidations after a grant check. Offline text requires opt-in and has a bounded lifetime. Reconnect, sign-out and account changes trigger a scope check or local removal. [Live connections](src/live.ts), [offline data](src/ops/offline.ts#L5) and [device handling](web/offline.tsx#L15). |
| Operator to cloud resources | Bind deployments and restores to their intended account, environment and destination. Protect release credentials and the signing key. | The guided installer checks the selected account, domain ownership and storage bindings. Upgrades record the previous Worker version and database bookmark. The signing key is wrapped under the stage setup secret. Recovery targets separate storage and disables restored users and pending dispatch. [Installer checks](scripts/cloud-install.mjs), [key management](src/instance-key.ts#L24) and [restored records](staging/restore-worker.ts#L42). |

## Scenarios to maintain in verification

- **Cross-mailbox disclosure has high impact.** An authenticated reader controls URLs, IDs and query parameters. Test direct reads, search, draft and Sent privacy, stale signed links and WebSocket updates after revocation. Users with valid read access can copy bytes they already received.
- **An email can carry deceptive links or harmful files.** Check that external images stay blocked, disallowed elements are removed, the frame has an opaque origin, and file downloads use restrictive headers. A user can still choose to open a downloaded file or visit a displayed destination.
- **Offline copies extend the lifetime of previously authorized data.** A disconnected device cannot learn about a server-side revocation until it reconnects. The device owner controls the local browser profile. The expiry and account-switch journeys exercise the application’s handling of that boundary.
- **Repeated sends or retries can affect recipients and consume quota.** Race submissions and simulate an acknowledgement loss. Exercise authorization again at dispatch, including scheduled sends. Keep a provider acceptance, a delivery event and a received envelope distinguishable in operator evidence.
- **Lost receipt metadata can make Bcc and alias mail unrecoverable.** Exercise a successful R2 put followed by a failed queue handoff. Restore a consistent snapshot into isolated resources and check its search index, private envelope, wrapped key and disabled outbound state.
- **Release authority can change real mail flow.** Keep the old receiver available through MX propagation. Verify the envelope at each service and restore the saved DNS record set. The disposable-domain rehearsal demonstrated that the first message after a DNS change can still reach the preceding provider.

This public preview has no published independent security assessment. The independent review should cover OAuth consent and refresh rotation, recursive grant revocation, Dynamic Worker isolation, mailbox owner notifications, webhook signature verification, remote images, and whether erasure persists through restore. The executable verification and external observations are in [TESTING.md](TESTING.md) and [DEPLOY.md](DEPLOY.md).

Report a suspected vulnerability with a [private security advisory](https://github.com/tannerwj/edge-mail/security/advisories/new). Use fictional messages in reproduction steps.
